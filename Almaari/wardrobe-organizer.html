Wardrobe Organizer

An interactive Wardrobe organizing dashboard where users can upload pictures of clothing items with filtering, create outfits and get tips from Almaari! an AI assistant.


No longer have to worry about finding your clothes in your messy wardrobe. Or spend hours sorting through your clothes to find the perfect outfit. All you have to do is upload your clothes, and the dashboard will do the rest.

Frontend Architecture Overview

A UX-focused, real-user dashboard frontend designed for clarity, speed, and an app-like experience.

  • App-like navigation with overlays and preserved state
  • React Query caching cuts re-fetches by ~60–70%
  • Auth-aware data access and protected UI flows

Frontend Architecture & Routing Strategy

Built with Next.js (App Router) and React, intentionally designed as a single-page dashboard. Dashboard views switch via internal view state rather than route navigation.

  • Supports overlay-based flows
  • Preserves layout state
  • Avoids unnecessary remounts
  • Delivers an app-like experience

Overlays include the Add Clothes flow and the Outfit creation UI.

State Management — Global UI & Domain State

Managed with Zustand for minimal overhead and ergonomic APIs.

  • Sidebar/menu visibility
  • Clothing filters (color, type, search)
  • Lightweight domain state shared across views

State Management — Server State

Managed with React Query for fetching, caching, pagination, and background revalidation.

  • Dedicated to server state (data from the API)
  • Decoupled from UI state held in Zustand
  • Predictable cache lifecycles and invalidation

Explicit separation between UI state and server state improves maintainability.

Data Fetching, Performance & Caching

  • REST API integration via custom hooks
  • useInfiniteQuery enables infinite scrolling of paginated clothing data
  • Auth-aware fetching (queries enabled only when an Auth0 user exists)

Before React Query: data was refetched on every view switch. After React Query: re-fetches reduced by approximately 60–70%. Cached pages render instantly when returning to a view — a clear, user-perceived improvement.

Authentication & Protected UI

  • Auth0 integration using @auth0/nextjs-auth0
  • Conditional rendering based on authentication state
  • User-scoped API calls and prevention of premature fetches
  • Graceful unauthenticated fallback UI

AWS S3 Image Storage Pipeline

Implemented a secure, scalable upload flow using presigned URLs to avoid routing large files through the backend.

  1. Frontend requests a presigned URL from the backend.
  2. Backend generates the signed URL using the AWS SDK.
  3. Frontend uploads the image directly to S3.
  4. Backend saves an image reference in the database.

Data Architecture & Design

MongoDB with three main collections:

  • User
  • Clothes
  • Outfits

Each clothing item and outfit is stored as an independent document linked to a user ID. This increases modularity and scalability as the platform grows. Indexes are created on the userId, type, and colour fields to improve query performance.

Schema Implementation (Mongoose) 


            // Clothes Schema
const ClothesSchema = new mongoose.Schema({
  userId: { type: mongoose.Schema.Types.ObjectId, ref: "User", required: true },
  uniqueId: { type: String, required: true, unique: true },
  type: { type: String, required: true, index: true },
  imageSrc: { type: String, required: true },
  favourite: { type: Boolean, default: false },
  createdAt: { type: Date, default: Date.now },
  colour: { type: [String], required: true },
  season: { type: [String], default: [] },
  waterproof: { type: Boolean, default: false },
  slot: { type: String, required: true }, //head, body, legs, feet
});

ClothesSchema.index({ userId: 1, createdAt: -1 });
ClothesSchema.index({ userId: 1, type: 1, createdAt: -1 });
ClothesSchema.index({ userId: 1, colour: 1, createdAt: -1 });

const Clothes =
  mongoose.models.Clothes || mongoose.model("Clothes", ClothesSchema);

// Outfits Schema
const OutfitsSchema = new mongoose.Schema({
  uniqueId: { type: String, required: true, unique: true },
  name: { type: String, default: "" },
  favourite: { type: Boolean, default: false },
  createdAt: { type: Date, default: Date.now },
  colour: { type: [String], required: true },
  season: { type: [String], default: [] },
  waterproof: { type: Boolean, default: false },
  outfit_items: [{ type: mongoose.Schema.Types.ObjectId, ref: "Clothes" }],
});

const Outfits =
  mongoose.models.Outfits || mongoose.model("Outfits", OutfitsSchema);

// User Schema
const usersSchema = new mongoose.Schema({
  auth0Id: { type: String, required: true, unique: true, index: true },
  email: { type: String, required: true },
  clothes: [{ type: mongoose.Schema.Types.ObjectId, ref: "Clothes" }],
  outfits: [{ type: mongoose.Schema.Types.ObjectId, ref: "Outfits" }],
  hasCompletedOnboardingForClothes: { type: Boolean, default: false },
  hasCompletedOnboardingForOutfits: { type: Boolean, default: false },
});

Trade-offs & Future Work

  • MongoDB excels for operational workloads (frequent writes, flexible schema), but complex analytics require heavier aggregation.
  • Future enhancement: hybrid system using PostgreSQL for analytics while keeping MongoDB for operations.

Impact & Outcomes

  • Reduced API response times by 25% through query optimization and indexing.
  • Improved data reload speeds using Redis caching.
  • Designed scalable cloud architecture supporting seamless deployment and growth.
